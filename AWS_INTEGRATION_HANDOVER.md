### Update 2026-10-11: plan gaps B and I closed; six new AWS services (all opt-in)
Still nothing deployed. Local checks: 151 tests pass (+4 frontend `npm test`), `cfn-lint` and `sam validate --lint`
clean, smoke 10/10, canary script passes against the local app. API shapes were checked against the AWS docs and
the installed botocore models (geo-maps GetStaticMap, bedrock CreateModelInvocationJob, socialmessaging
SendWhatsAppMessage, connect StartOutboundVoiceContact).
- **B, walking steps**: the route request asks for `TravelStepType: Default` + `LegAdditionalFeatures:
  [TravelStepInstructions]` + `Languages` (Instruction text exists only for the Default step type). Steps are parsed in
  `frontend/src/routeParse.js` (unit-tested with `npm test`) and listed under the citizen route map.
- **I, map in the HTML card**: `api/static_map.py` renders one Amazon Location static map per city per alert day
  (numbered red zones, blue cool refuges not reported full/closed), signed with the Refresh role (no API key in
  email), stored at `<site>/alert-maps/<city>/<date>.jpg` in the frontend bucket (deploy.sh sync excludes that folder).
  Style defaults to `Satellite` (the developer guide says static maps support Satellite; override STATIC_MAP_STYLE).
- **Bedrock batch inference** (`ENABLE_BATCH_BRIEFS=1`, needs a model id): `agent/batch_briefs.py`,
  `lambdas/brief_batch/app.py`. 00:30 IST: one optimiser run per city, 906 Converse-format records (~2.2 MB, ~1 min
  to build) -> CreateModelInvocationJob (24 h timeout). EventBridge "Batch Inference Job State Change" -> collect:
  same number check as live briefs, failures become template briefs, cache `briefs_cache/<city>/<ward>.json`.
  `/api/v1/brief` serves the cache for default budget/equity while < 36 h old (`fresh: true` forces a live brief).
- **CloudWatch Synthetics** (`ENABLE_SYNTHETICS=1`): `infra/canary/python/heartbeat.py` (stdlib only) checks
  /health, /risk/today, /citizen and the citizen page every 5 min; runtime `syn-python-selenium-12.0` (parameter
  `CanaryRuntime`); zip uploaded by deploy.sh (two-pass on a brand-new stack); alarm on SuccessPercent to OpsTopic.
- **Secrets Manager** (`ENABLE_SECRETS=1`): officer token generated by the stack; `api/auth.py` reads it (5-min
  cache) and fails closed (503) if it cannot. The WAF edge secret is still a plain parameter (next candidate).
- **Kinesis Data Firehose** (with `ENABLE_IOT_SENSORS=1`): IoT rule also writes every reading to
  `s3://<data>/sensors/history/dt=YYYY-MM-DD/` (gzip JSON, 400-day lifecycle); Glue table `sensor_history` + named
  query when analytics is on.
- **WhatsApp alerts** (`WHATSAPP_PHONE_NUMBER_ID=...`, End User Messaging Social) and **phone calls**
  (`CONNECT_INSTANCE_ID` + `CONNECT_CONTACT_FLOW_ID`, Amazon Connect + Polly): `api/phones.py`, `api/whatsapp.py`,
  `api/voice_calls.py`, `api/routers/phone_alerts.py`. Numbers: consent required, WhatsApp double opt-in, signed
  confirm/unsubscribe links (HMAC key generated in Secrets Manager), masked on screens, hashed in logs, DynamoDB TTL
  one year (48 h for unconfirmed). Voice contacts are added by ward officers only (consent note recorded). A
  simulated alert never messages or calls anyone. Calls are capped by `MAX_CALLS_PER_RUN` (default 10).
  **Manual setup before switching on:**
  1. WhatsApp: link a WhatsApp Business account in AWS End User Messaging Social; create and get approved two
     templates: `heatrelief_optin` (body `{{1}}` city, `{{2}}` confirmation link) and `heatrelief_alert` (body
     `{{1}}` city, `{{2}}` level, `{{3}}` forecast high °C, `{{4}}` top zones, `{{5}}` advice, `{{6}}` citizen-page
     link, `{{7}}` unsubscribe link).
  2. Connect: create an instance, claim a number, and a contact flow: Set voice (Kajal, from `$.Attributes.voice`) ->
     Play prompt, text-to-speech from `$.Attributes.message` -> Disconnect. Pass instance id, flow id and the number.
- New tests: `test_static_map.py`, `test_batch_briefs.py`, `test_canary.py`, `test_secrets_token.py`,
  `test_phone_alerts.py`, `test_template_wiring.py` (the last catches env vars wired to the wrong function — it found
